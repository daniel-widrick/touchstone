Getting started

harbour makes encrypted, de-duplicated backups of your folders to a local disk or to any S3-compatible storage. This page takes you from nothing installed to a first backup, a test restore, and a nightly schedule.

Before you start

Operating system
macOS 12 or later, Linux with glibc 2.31 or later, or Windows 10 or later
Disk space
About 60 MB for harbour itself, plus room for your backups
Dependencies
None

The examples back up ~/Documents to a repository at /mnt/backup/repo. Swap in your own folder and repository location wherever you see them.

1Install harbour

macOS

Install with Homebrew:

brew install harbour

Linux

Run the install script:

curl -fsSL https://get.harbour.example/install.sh | sh

Windows

Install with winget:

winget install Harbour.Harbour

Then check that it worked:

harbour --version

You should see a version number starting with 2.4. If the command is not found, open a new terminal window and try again.

2Create a repository

A repository is where harbour stores your backups. Create one on the disk you want to back up to:

harbour init /mnt/backup/repo

harbour asks you to type a passphrase, then to type it again to confirm. Everything in the repository is encrypted with it.

Your passphrase cannot be recovered

If you lose it, nobody can read your backups, including us. There is no reset. Before you go on, save it in a password manager or write it down and keep it somewhere safe, away from the computer you are backing up.

Using S3-compatible storage instead

To keep backups in a bucket rather than on a local disk, first put your storage access key and secret in the environment.

macOS and Linux

export HARBOUR_S3_KEY="your-access-key"
export HARBOUR_S3_SECRET="your-secret-key"

Windows (PowerShell)

$env:HARBOUR_S3_KEY = "your-access-key"
$env:HARBOUR_S3_SECRET = "your-secret-key"

Then create the repository, using your own bucket name and path:

harbour init s3://bucket-name/path

In the rest of this page, use your s3:// address wherever you see /mnt/backup/repo. The two variables need to be set in every terminal session where you run harbour.

3Make your first backup

Back up a folder by naming it and the repository:

harbour backup ~/Documents --repo /mnt/backup/repo

The first run copies everything, so it can take a long time. Later runs only send what has changed and are much quicker.

4See what is stored

harbour list --repo /mnt/backup/repo

Each backup is called a snapshot. Every snapshot has an id such as a1b2c3d4, which is what you use to restore it.

5Restore files

Take a snapshot id from harbour list and choose a folder to restore into:

harbour restore a1b2c3d4 --to ~/restored --repo /mnt/backup/repo

Replace a1b2c3d4 with your own snapshot id.

harbour never overwrites existing files when it restores. If you do want files in the destination replaced, add --overwrite to the command.

Try a restore now

Restoring your first snapshot into an empty folder and opening a few files is the surest way to know your backups work before you need them.

6Back up every night

On Linux and macOS you can use cron to run a backup every night at 02:00. Open your crontab for editing:

crontab -e

Add this line, then save and close the editor:

0 2 * * * harbour backup ~/Documents --repo /mnt/backup/repo --quiet

The first two fields are the minute and the hour, so 0 2 means 02:00. Change them to run at a different time.

Common problems

repository is locked

Another harbour process is using the repository, or an earlier one crashed and left its lock behind. If a backup is still running, wait for it to finish. If you are sure nothing is running, remove the lock:

harbour unlock --repo /mnt/backup/repo

wrong passphrase

Check that caps lock is off and that your keyboard layout is the one you used when you created the repository, then try again. There is no way to reset a passphrase.

permission denied reading a file

harbour skips any file it is not allowed to read and carries on with the rest. When the backup finishes, it lists the files it skipped. To include them, run the backup with sudo:

sudo harbour backup ~/Documents --repo /mnt/backup/repo
