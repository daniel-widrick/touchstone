Getting started

harbour makes encrypted, de-duplicated backups of your folders to a local disk or to any S3-compatible storage. This page takes you from nothing installed to a backup that runs every night.

What you will do

  • Install harbour and create a place to store backups.
  • Back up a folder, look at what was stored, and restore it.
  • Schedule the backup to run on its own.

Before you start

harbour runs on any of these, and needs nothing else installed:

SystemMinimum version
macOS12 or later
Linuxglibc 2.31 or later
Windows10 or later

You also need about 60 MB of free disk space for harbour itself, plus room for your backups wherever you choose to keep them.

The examples on this page back up ~/Documents into a repository at /mnt/backup/repo. Replace both with your own paths as you go.

Step 1Install harbour

Pick your system and run the command in a terminal.

macOS

Install with Homebrew:

brew install harbour

Linux

Download and run the install script:

curl -fsSL https://get.harbour.example/install.sh | sh

Windows

Install with winget:

winget install Harbour.Harbour

Then check that it worked:

harbour --version

You should see the version number, 2.4. If the command is not found, open a new terminal window and try again.

Step 2Create a repository

A repository is where harbour stores your backups. You create it once, then every backup goes into it. It can live on a local disk or in S3-compatible storage.

On a local disk

harbour init /mnt/backup/repo

On S3-compatible storage

First put your storage access key and secret in the environment, so harbour can sign in:

macOS and Linux

export HARBOUR_S3_KEY="your-access-key"
export HARBOUR_S3_SECRET="your-secret-key"

Windows (PowerShell)

$env:HARBOUR_S3_KEY = "your-access-key"
$env:HARBOUR_S3_SECRET = "your-secret-key"

Then create the repository, using your own bucket name and path:

harbour init s3://bucket-name/path

Choose a passphrase

Either way, harbour init asks you to type a passphrase, then type it again to confirm. This passphrase encrypts everything in the repository, and you will need it to read your backups.

The passphrase cannot be recovered

If you lose it, nobody can read your backups, including us. There is no reset. Before you go on, save it in a password manager or write it down and keep it somewhere safe, away from the computer you are backing up.

Step 3Make your first backup

Tell harbour which folder to back up and which repository to put it in:

harbour backup ~/Documents --repo /mnt/backup/repo

The first run copies everything, so it can take a long time. Let it finish. Later runs only send what has changed, and are much quicker.

Step 4See what is stored

harbour list --repo /mnt/backup/repo

Each backup is called a snapshot. Every snapshot has an id that looks like a1b2c3d4. You use that id to restore from it.

Step 5Restore files

Give harbour a snapshot id from the list and a folder to restore into. Replace a1b2c3d4 with one of your own ids:

harbour restore a1b2c3d4 --to ~/restored --repo /mnt/backup/repo

harbour never overwrites files that already exist. If you do want existing files replaced, add --overwrite to the command.

Try a restore now

A backup is only useful if you can get your files back. Restoring into an empty folder such as ~/restored is safe, and shows that the repository and your passphrase both work.

Step 6Back up every night

On Linux and macOS you can use cron to run the backup on a schedule. Open your crontab for editing:

crontab -e

Add this line, then save and close the editor:

0 2 * * * harbour backup ~/Documents --repo /mnt/backup/repo --quiet

The backup now runs every night at 02:00. The first two numbers set the time, minute 0 of hour 2, so change them if another time suits you better. The computer has to be switched on at that time for the backup to run.

This schedule is for Linux and macOS only. Cron is not available on Windows.

Common problems

repository is locked

Another harbour process is using the repository, or an earlier one crashed and left its lock behind. If a backup is still running, wait for it to finish.

If you are sure nothing is running, remove the lock:

harbour unlock --repo /mnt/backup/repo

wrong passphrase

Check that caps lock is off and that your keyboard layout is the one you used when you created the repository, then type the passphrase again. There is no way to reset a passphrase.

permission denied when reading a file

harbour skips any file it is not allowed to read and carries on with the rest. When the backup finishes, it lists the files it skipped. To include them, run the backup again with sudo:

sudo harbour backup ~/Documents --repo /mnt/backup/repo
